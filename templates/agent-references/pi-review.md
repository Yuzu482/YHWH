## Independent budgets and mandatory review packet

T1/T2 reviews use medium by default, or high/xhigh (extra) when the primary identifies concrete review complexity under pi-routing. Send thinking explicitly and record the reason in task.context. Tier, security-related scope and packet size do not alone force max. Effort selection never changes review attempt limits, independence, required evidence or T1's 10 KB limit; normal reviews do not accept max.

Use queueTimeoutSeconds (default 120, maximum 900) for queue admission and timeoutSeconds for execution. Profile defaults remain 120/300/900 seconds; an explicit execution timeout may extend small/standard profiles up to the global 900-second hard ceiling. CPU, memory, PID, output, and scheduler capacity remain fixed. Prefer submit_subagent and inspect waitReasons, queueWaitMs, executionMs; waiting does not consume execution time. Do not reduce host reserve or change providers to evade admission.

Every Geburah/reviewer task must carry task.reviewPacket with version 1, stage pre-change or post-change, and requirements, changes, context, verification sections. Each section contains status (provided, missing, or not-applicable), content (actual excerpt strings), and optional reason. Only changes/verification may be not-applicable with explicit justification. Supply actual diffs/context/test evidence; inaccessible filenames and test plans are not proof that checks ran. Missing required material blocks before model execution. The reviewer must question incomplete or contradictory evidence. Default output adds reviewDecision and missingMaterials. Approve with completed status, evidence and no missing materials passes. For T1, findings explicitly classified nonblocking mean conditional approval and no re-review; blocking findings or insufficient materials keep work incomplete. T2 review limits survive repair/relabeling. Keep Sonnet access none and do not recursively delegate. Material structure is machine checked; semantic completeness and final acceptance remain with reviewer and primary.

## Avoid wasting a review slot

Before dispatch, the primary checks the whole task's review stage and used attempts, then compares reviewPacket against the actual changed-file list. Include concrete diff hunks for every changed file, including tests, documentation and fixtures, plus the relevant source context and real host checks. A filename or prose summary alone is not a file diff. Keep T1 packets within 10240 serialized UTF-8 bytes; if complete material cannot fit, stop and resolve scope/material delivery without splitting the task, silently truncating evidence or launching an exploratory review.

Use deterministic preparation to split complete real material into valid section strings and inspect coverage/serialized UTF-8 bytes before submission. Validate expanded artifact material before model launch, not only a small reference. Artifact references must resolve to the same trusted ledger implementation, digest and identity; arbitrary caller paths are not review evidence. Hydrate/redact before checking the byte limit; stale, inaccessible, missing-file or oversized evidence fails closed without a model call. Preserve the caller's original idempotency payload. Do not omit generated changes unless a complete deterministic equivalence proof against authoritative inputs is actually available; otherwise include their real diffs and report the compression limitation.

Request concise schema-complete findings and evidence; do not ask the reviewer to reproduce supplied diffs. Before any repair review, close each blocking or missing-material item from the previous result and revalidate the packet. Do not resubmit after approval or conditional approval. An insufficient-materials or malformed-output result after actual model launch still consumes its slot; queue/admission or confirmed zero-launch rejection does not. Never refund a timeout or uncertain execution merely because it produced no usable result.

Apply the elastic quota below across repairs, phases, request-ID changes and restarts. When its count, time or progress gate is exhausted, report the original attempt outcomes and escalate to the user; do not automatically follow a reviewer's suggestion to re-review, change the run identity, increase effort or clear the ledger. Distinguish deterministic file-coverage checks from semantic material completeness, which remains the primary's and reviewer's responsibility.

## Evidence-gated elastic quota (2026-10-06)

Activate only when live capabilities advertise elasticReviewQuota.version=2 (or workflowTiers.reviewQuota.version=2). Until then obey the deployed hard caps: T1 one post-review, T2 two per stage. This implementation task does not use its proposed extension to authorize itself.

| Tier | Base quota | Maximum | Aggregate reviewer execution |
| --- | --- | --- | --- |
| T0 | None | None | None |
| T1 | One post-review | One evidence-gated extra; total two | 600000 ms (10 minutes) |
| T2 | Two per stage | One extra shared across stages; stage three, task five | 1200000 ms (20 minutes) |

All counts and time belong to the whole goal, including repairs, phase continuation, new IDs and restart. Bind canonical workspace and goal anchor; a non-null parent alias cannot change anchor to reset quota, and a new parent cannot reset the same anchor. Missing parents create no shared alias bucket. Tier changes do not reset/refund. Legacy records lack parent identities and cannot safely establish aliases. Queue time is separate; actual reviewer execution consumes time, with milliseconds rounded down to admitted integer seconds. Reject insufficient viable execution time before launch; elapsed beyond reservation is still charged, with remaining clamped to zero. Missing tokens remain unavailable.

Additional eligibility requires one bounded typed REVIEW_PROGRESS_JSON= context entry, referencing the prior failed review and closure evidence for every persisted blocking/missing-material key. Gateway resolves the trusted decision, stage/phase/goal, digests and affected paths; caller assertions, changed IDs, repeated packets or unrelated edits confer no credit. Pre-review needs actual changed complete plan material with relevant revised sections. Post-review needs a different trusted repaired artifact and complete current passing artifact-bound host evidence. Deterministic checks establish identity and coverage only; primary and reviewer still judge semantic relevance and actual blocker resolution. Malformed output/timeout with no actionable blockers is ineligible for automatic extension.

Approve/conditional approval stops unnecessary review. An unchanged phase/stage/material cannot be reviewed again. A necessary later correction with a different artifact/plan invalidates previous approval and requires current evidence; only remaining base quota may be used after that approval, never an extension. Legitimate v2 phase continuation preserves total counts/time. Compare normalized blocker/missing-material keys (lowercase and collapsed whitespace, severity and cited paths/sections); two consecutive identical or non-shrinking blocker sets without verified progress stop automatic retry. Exhausted counts, time, missing trustworthy progress or ambiguous identity require user escalation with original outcomes.

Reserve counts and worst-case execution allowance atomically before launch; serialize pending reviews of the same goal. Confirmed zero-model execution releases reservation; started timeout and uncertain execution consume it. Crashed/pending tickets retain conservative allowance and fail closed with the attempt identity for operator reconciliation. Old v1 stage records are validated and imported idempotently on every admission, including later old-runtime writes; old consumed/unknown time remains unknown and conservatively charged against the legacy 900-second ceiling. Migration never deletes history. Missing validated decisions cannot unlock an extension, including a crash after execution finish and before decision persistence.

Compact T1 repairs must retain the original implementation objective and acceptance (the standalone goal anchor), placing correction details in context. Linked T2 repairs retain runGoal/runAcceptance and phase identity. Changing these fields is not a repair mechanism: ambiguous changes fail closed rather than start a new budget.

Implementation dispatches remain separate: coordinator-only initially allows three, then diagnosis/reassessment. This quota grants no deployment, identity override, ledger clearing, provider substitution or primary-direct authority.
