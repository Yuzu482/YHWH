# Delegation

The primary chooses whether to implement directly or delegate based on task independence, available tools, risk and current host instructions. Pi and built-in agents can be used when helpful and permitted. Do not create duplicate writers on overlapping work. Preserve scope, actual outputs, failure history and user-approved limits.

These descriptions apply to Pi gateway calls, which still enforce their advertised routing, tier, review and ledger rules. They do not govern direct host work. Follow higher-priority instructions and the current user request; preserve existing task identities, quotas and history. A topic or receipt does not grant authority.

Pi calls remain subject to the gateway's actual role, provider, scope and tier checks. Use list_capabilities and pi-routing for current availability; do not describe an unexecuted review as passed.
