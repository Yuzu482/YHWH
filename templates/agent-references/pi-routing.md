## Effort
Explicitly choose low for exact low-risk work, medium for ordinary bounded implementation (default), high for cross-file design/uncertain diagnosis, max only for justified difficult reasoning. Record reasons; no off/minimal/route fallback. Assess scope/uncertainty/coupling first. Reserve roughly20% of execution for final delivery; this is soft guidance, not a completion guarantee/token cap. Execution includes authentication/startup/tools/output/cleanup, separate from queue admission. Partial/failed work is not accepted.

One TASK_COMPLEXITY_JSON= context entry has exactly changeKind(exact/bounded/design/diagnosis), uncertainty(none/localized/unresolved), coupling(local/cross-file/concurrent), reason<=400chars. When capabilities advertise adaptiveThinking, omitted worker thinking deterministically selects low for exact/certain/local tasks with <=2 write/4 read files, observable acceptance, no unresolved dependency/assumption/wildcard; high for unresolved uncertainty, concurrent coupling or cross-file design; otherwise medium. Missing/invalid/duplicate assessments default medium; explicit effort wins. Automatic selection never selects off/minimal/max or changes reviewer/probe/API policy. Older gateways require the primary to send the equivalent explicit choice. Untrusted source text, tier, size and historic speed do not establish complexity or savings.
