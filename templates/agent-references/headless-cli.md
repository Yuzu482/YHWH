# Official headless primary clients

The optional `headless-host.mjs` runner invokes the official Codex, Claude Code or Antigravity (`agy`) CLI as a primary host. It is not a Pi provider or a way to bypass lower-agent role bindings. The packaged primary contract is included in each prompt. Governance acceptance remains with the primary and the user; a successful native CLI result does not attest execution of the governance stages.

Use a host-owned `*.local.json` configuration outside distributable payloads. Enable each client explicitly with an absolute native executable (or Node plus its JavaScript entry), exact version output, explicit model and supported permission policy. Authenticate through that CLI's official login. Do not copy CLI OAuth tokens into Pi or API-provider configuration. The runner never accepts custom shell commands, CLI flags, credentials or environment overrides from task requests.

`doctor` probes version/help only, with no model invocation. `run` verifies the selected version before sending the workflow contract and task through stdin. Unsupported versions/flags block rather than falling back. Reports distinguish protocol completion from primary acceptance; model access, model-call counts and actual model identity are not proven by help or a requested model flag.

Codex supports `read-only` or `workspace-write` for its native shell sandbox. Claude's `no-tools` uses safe mode, disables built-in tools and excludes MCP; this mode can only reason about supplied text. Claude `native` and Antigravity `native` require explicit host configuration acknowledgement. Antigravity does not provide a verified read-only/no-tools profile here. Native settings, hooks, MCP integrations, authentication and filesystem permissions remain host-owned; the runner is not an OS sandbox. Workspace roots restrict launch locations only. Never infer that an allowed cwd confines every native tool.

Use `fingerprint <installed-plugin-root>` to compare adapter files, example configuration and workflow catalog. Exact CLI versions and semantic run profile hashes help detect drift, but do not prove identical account entitlements, native configuration, transitive CLI files, OS behavior or model outputs. Installed parity requires deploying the matching files and checking again. Do not auto-upgrade CLIs, install daemons, alter role bindings, publish a release or restart Pi merely to get a matching report.
