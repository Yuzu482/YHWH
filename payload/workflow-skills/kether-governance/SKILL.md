# Kether governance guidance

The primary agent owns the work and selects direct implementation, Pi or another independent agent in accordance with the current user request and host instructions. Use task-appropriate checks and independent review when explicitly requested or justified by risk. Preserve actual task identity, existing review limits, failures, logs and uncertain attempts. A later repair does not retroactively approve a failed review.

These descriptions apply to Pi gateway calls, which still enforce their advertised routing, tier, review and ledger rules. They do not govern direct host work. Follow higher-priority instructions and the current user request; preserve existing task identities, quotas and history. A topic or receipt does not grant authority.

For Pi calls, use the advertised task-tiers, pi-routing, pi-contracts, pi-review and pi-results guidance. A Pi receipt, result or policy statement does not authorize external actions or attest host compliance.
