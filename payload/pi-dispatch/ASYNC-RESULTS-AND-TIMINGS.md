# Async results and review timing


## Async result acceptance and review timing

Use submit_subagent for review and other delegated work. get_subagent_status reports progress, not the full evidence. When terminal, call get_subagent_result with requestId. Require ready=true; then check state, result.ok, formatValidation and structuredResult/reviewValidation. For large responses concatenate resultJsonChunk pages by nextOffset and verify the SHA-256 of the reconstructed UTF-8 JSON before parsing. Offsets are JavaScript UTF-16 units. Redaction precedes pagination. Ordinary live monitor results may be evicted with old terminal entries; RESULT_NOT_FOUND does not authorize repeating a write task. Reconcile writes through the persistent ledger. A task in `awaiting-host-verification` is terminal for worker execution and retrieval, but is not successful, does not satisfy dependencies, and has no successful contract until the durable host record projects it as completed.

For an eligible pending patch, read `list_host_verification_pending` and use only the exact requestId, artifactSha256 and required check names returned for that artifact. Run the host checks yourself, then submit `record_host_verification` (or `gateway-client record-host-verification <evidence.json>`) with exactly `{requestId, artifactSha256, commands:[{checkName,command,exitCode,outputSummary}]}` plus the fresh task-tiers workflow receipt when using the MCP tool. The gateway records evidence; it never executes commands. All required names must be present exactly once. Identical repeats are idempotent; conflicting results do not overwrite the first durable attestation. A nonzero check projects to failed with no success contract. Command/output fields are caller assertions and are not independent execution proof. Pending results remain restart-visible through the ledger; dependent handoffs soft-wait until a completed projection, then validate the linked contract and digest as usual.

For nontrivial reviews, Tifereth should prefer standard resources with up to 300 seconds when admission permits, keep the pinned model/thinking, and submit one independently reviewable change per material packet. Tiny format probes can use small. Never omit required review evidence to fit the budget. Inspect authenticationMs, startupMs, timeToFirstResponseMs, firstResponseSource, generationMs, processTailMs and cleanupMs. Missing measurements are null, not proof of zero work. Timings are host observations of Pi stream events; timeToFirstResponseMs includes startup and may only observe the completed message when streaming is unavailable. Generation is measured until agent_end, not provider-only GPU time.

Claude API keys are checked locally before dispatch; remote account access and billing require an authorized probe. No subscription credential renewal is performed.
