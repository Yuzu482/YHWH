YHWH 默认启用 `strict` 模式，在受管模型执行前检查 worker 路由，包括无文件权限但可以输出代码的请求。普通 worker 仅允许原生 `openai-codex/gpt-6-luna`，或宿主已配置且语义模型为 Luna 的 `yhwh-worker-api`。Sol、Terra 等模型可以由外部宿主选择为主模型，但不能作为普通 Pi worker 执行。

仅保留两类受控例外：通过现有角色绑定、完整审查材料和无工具权限检查的 Sonnet reviewer，以及网关生成固定回显内容的无工具心跳。任务不能靠填写 reviewer 名称或增加 probe 字段取得例外。模型发现列表用于查询和探测，不代表 worker 执行许可。

独立无头 CLI 会绕开 Pi 的角色验证，因此严格模式拒绝其模型执行，包括单次、会话、批次和流式入口；版本、帮助、Doctor 与文件指纹检查仍可使用。需要原有无头 CLI 行为时，由宿主操作者显式关闭这个附加限制。

## 开关

宿主进程环境变量 `YHWH_WORKER_ENFORCEMENT` 只接受两个精确值：

| 值 | 行为 |
| --- | --- |
| 未设置或 `strict` | 启用限制 |
| `off` | 关闭附加限制，恢复原有入口行为 |
| 其他值，包括拼写错误 | 拒绝执行，不默默退回宽松模式 |

在启动 YHWH 的 PowerShell 窗口中设置 `$env:YHWH_WORKER_ENFORCEMENT = 'strict'` 或 `'off'`，然后使用正常流程启动服务。已经运行的服务不会继承另一个终端新设置的环境变量，需要按既有升级/重启流程重启。临时终端设置不会自动持久化到下次登录。通过 `list_capabilities.workerEnforcement` 检查运行中的实际模式。

开关不接受任务参数、工作区配置或每次请求覆盖，也不会传给 Pi 子进程。关闭开关不改变原有角色、provider、审查材料、文件权限和授权约束，不自动授权主代理编码，也不触发其他模型回退。

## 边界

这里的“硬限制”是 YHWH 管理的入口在调用认证或启动模型进程前拒绝请求。它不撤销外部 Codex、Claude 或其他客户端自身的终端/编辑器权限，也不能阻止拥有宿主权限的操作者修改代码或改变开关。主代理的外部工具使用仍受 [主代理职责](coordinator-only.md) 约束；不要把能力元数据或一次心跳成功当成操作系统隔离或全部历史合规的证明。
