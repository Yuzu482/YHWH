# OpenDesign / 生成式页面适配

[简体中文](generated-page-adapter.md) | [English](generated-page-adapter.en.md)

本说明适用于检查或修改由生成器输出的页面源码；它不授予浏览器、开发者工具或本地服务的访问能力。

## 大型单行 HTML 的源码读取

worker 可在任务确实提供该工具时使用受控 `yhwh_source_window`，从 worker 工作目录内的 UTF-8 常规文件读取有限源码窗口。路径必须是相对路径；不允许符号链接或越出工作目录。可用精确 `query`（可用 1 起始的 `occurrence` 选择出现次序），或用零起始 `offset` 指定位置，二者不可同时提供。offset、返回边界及长度采用 UTF-16 code units。每次最多返回 8000 个 UTF-16 单位（默认 4000）；文件上限为 8 MiB。返回信息含完整文件字节的 SHA-256、总 UTF-16 长度、窗口起止位置及截断标记。SHA-256 标识被读取的完整文件，不表示页面运行结果。

该工具只在 WSL2 worker 的受控执行中提供，且文件访问仍受任务 `readScope`、沙箱和访问级别约束。`read` 不等于写权限；写入还要求获准的 `workspace-write` 及任务 `writeScope`。不要通过窗口工具推断或绕过范围限制。

## 阶段任务包与验收

- 将 worker 任务限定为指定源码范围内的交付，并要求可核对的静态证据；明确路径、预期产物和验收标准。
- 浏览器交互、渲染、响应式布局或本地服务验收，应交给具有相应授权与能力的后续阶段，不应暗示源码 worker 已经执行这些检查。
- 如果浏览器验收属于当前阶段的 required acceptance，缺少浏览器证据就不能把任务标为完成；应报告未验证/阻塞并说明缺失证据。
- 真实工具错误会使网关拒收，即使最终文字声称成功，也不能忽略错误或将其改写为通过。

不存在浏览器能力的自动授权。需要浏览器验收时，必须由宿主明确提供对应工具、权限及验收阶段。

## 安装后自检与本地服务

`install/Test-PiKether.ps1` 可在安装后以 `-Installed` 检查插件依赖、Pi 入口、工作流目录、所选宿主 profile 和 MCP 工作区配置；默认还检查 WSL 中的 role-presets 与 source-window 扩展、扩展语法、沙箱/资源限制及 LSP 等组件。`-SkipWsl` 可跳过 WSL 检查。此脚本检查安装文件和组件，并不启动页面或证明浏览器验收成功；凭据存在也不代表模型访问有效。

源码树中的实现与已安装/运行中的本地服务不是一回事。修改源码不会自动更新已安装插件或 WSL 服务；需要按安装流程部署后，再针对实际目标运行自检。不要把自检通过、协议连通或静态源码证据说成页面已在浏览器中通过验收。
