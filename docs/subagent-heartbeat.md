# 子代理心跳

[简体中文](subagent-heartbeat.md) | [English](subagent-heartbeat.en.md)

通过 `submit_subagent` 提交的异步任务，其心跳由 Pi 网关的本地任务监管器产生，不调用模型。`get_subagent_status` 和 `list_subagents` 的任务记录提供 `heartbeat` 字段；同步派发和模型探针不在本功能范围内。它与 `probe_model` 不同：后者执行真实模型请求，不能当作日常保活计时器。

任务开始执行后每 10 秒更新一次监管心跳，超过 30 秒未更新时，读取状态会显示 `stale`。排队期间显示 `not-started`；取消或结束后停止心跳。序号和时间戳由实际计时器更新，读取任务状态不会伪造新心跳。

`heartbeat.source` 为 `gateway-supervisor`，`modelCalls` 为 `0`。这只证明本地监管回调曾运行，不证明 WSL 子进程、远端模型健康或模型正在生成。`lastProgressAt` 独立记录执行层最近的进度回调；没有进度不等于任务失联。

心跳过期不会自动取消、重试、重派任务或触发模型探针。原有队列/执行时限、请求账本和最终结果验收继续生效。终态和取消请求会清理计时器，后续迟到回调不能恢复心跳。

主代理仍遵守低轮询策略。任务状态接口返回心跳元数据，监控界面可以独立读取；这不是新增的完成事件订阅，也不会自动唤醒 Astra。网关整体不可达时，客户端应报告连接问题，不能依赖最后一份缓存状态声称任务仍健康。

修改仓库不会自动升级已安装的 Pi 服务。部署、重启、GitHub 推送和发布需要各自的授权与验证。
