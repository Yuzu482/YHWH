## Public synthetic tests

`tests/fixtures/legacy-state-pins.json` pins the runtime and mirrored dependencies.
The helper checks source hashes before loading copies, matches literal occurrence
counts, substitutes only listed immutable pins in a fresh temporary mirror, and
reverses all substitutions to require byte identity with the genuine source.
Behavioral numeric limits, predicates, imports and exported methods stay unchanged.
Untransformed dependencies must match their pins too. An intentional future source
change must deliberately update these pins; a hash failure is an intended tripwire.

Ledger prefixes and random attempt IDs are generated by genuine lifecycle APIs.
Recovery derives canonical workspace and milestone identity/definition first,
then prefix, proof bytes and their hashes. Windows paths are canonicalized using
the real identity module, with lowercase only on Windows. Tests include spaces in
paths and do not rely on any private historical folder or patch preimage.

Synthetic positives execute a pin-rebound **test copy**, proving algorithm and
lifecycle behavior. They do not prove historical cryptographic eligibility or a
newly successful production recovery. Unmodified-module negative cases, exact
source hashes and reversible substitution bind those tests to shipped code.
Public tests contain synthetic evidence only, not private task packets or reviews.

or new paths; no other distributed test is excluded:

## Private host evidence and rollback

Host checks read the current configured grant without publishing its authorization
document. API checks operate only on fresh copies of historical states: review
snapshot can lock or migrate files, so it is forbidden on live stores. A recovered
milestone copied to a different root may correctly fail its exact-root binding;
that result is retained as fail-closed parity, not described as positive recovery.
Installed and candidate outcomes, counts and digests are compared separately from
the synthetic public cases. Original source/config/state hashes are retained.

This candidate is uncommitted and undeployed. Rollback means discarding only this
isolated candidate after authorization; no live state requires rollback. Future
publication and deployment need separate user authorization and clean-main checks.
