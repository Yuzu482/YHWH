# Subagent heartbeats

[简体中文](subagent-heartbeat.md) | [English](subagent-heartbeat.en.md)

For asynchronous tasks submitted through `submit_subagent`, heartbeats are generated by Pi's local gateway task supervisor without model calls. Task records returned by `get_subagent_status` and `list_subagents` expose a `heartbeat` field; synchronous dispatch and model probes are outside this feature's scope. Heartbeats differ from `probe_model`, which executes a real model request and must not be used as a routine keepalive timer.

After execution starts, the supervisor updates a heartbeat every 10 seconds. Reading its status reports `stale` when no beat has occurred for more than 30 seconds. Queued tasks report `not-started`; cancellation or termination stops the heartbeat. Actual timer callbacks update sequence numbers and timestamps; status reads do not fabricate beats.

`heartbeat.source` is `gateway-supervisor` and `modelCalls` is `0`. This only establishes that local supervision callbacks ran, not that a WSL child or remote model is healthy or generating. `lastProgressAt` separately records the latest execution-layer progress callback. Missing progress does not establish task loss.

A stale heartbeat does not automatically cancel, retry, redispatch or run a model probe. Existing queue/execution deadlines, request ledger and final-result acceptance remain authoritative. Terminal states and cancellation requests clear the timer; late callbacks cannot restart it.

The primary retains its low-polling policy. Task status interfaces expose heartbeat metadata for independent monitoring. This is not a new completion-event subscription and does not automatically wake Astra. If the whole gateway is unreachable, clients must report connection failure rather than treating the last cached snapshot as current health evidence.

Repository changes do not automatically upgrade the installed Pi service. Deployment, restart, GitHub push and release require their own authorization and verification.
