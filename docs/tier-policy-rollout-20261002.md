## primary-direct 提案（待用户决定，当前不启用）

候选条件同时满足：整个任务的实际补丁增加+删除不超过 10 行；只改配置、文档或一个单行修复；五个语义风险均为 false；可以 Git 回滚；工作目录的有效 riskProfile 为 standard 或 personal。critical 项目一律不可使用。

防止滥用的限制：
- 以用户原始目标为聚合单位，累计所有直接修改和修复；不能拆成多个 10 行任务、换 requestId、改文件名或重置计数来绕过限制。
- 保留原分级与审查义务：修改共享模块或公共行为仍是 T1，须一次 high 事后审查；不得通过 primary-direct 标签跳过 T1 门禁。若要扩大免审范围，需另作明确政策决定，当前提案不包含该扩大。
- “一行修复”必须是局部表达式/拼写/明显错误；不能用压缩代码、生成代码、整段长行、模板替换或间接执行脚本隐藏大改。
- 配置不得改变权限、认证、凭据、网络暴露、模型绑定、审查门禁、部署目标、依赖或运行隔离；docs 不得通过可执行嵌入/生成过程改变程序。治理规则与网关配置不适用此例外。
- 写前记录目标、基线、允许路径及风险判定；写后由可信 Git 补丁统计验证限制并绑定摘要。遇到范围/风险不明先 scout；超限停止直接修改，保留并移交 worker，不继续补丁。
- 宿主运行适用检查，保存完整输出、退出码、补丁摘要和失败情况；无真实运行证据不能完成。宿主无法验证则走现有 worker/Netzach 路径。
- 独立审计类型 primary-direct，记录原任务 ID、cwd/riskProfile、文件、增加/删除行数、五风险字段、基线与补丁摘要、验证命令和结果；不伪造 Chesed 或独立审查。
- 网关只提供主代理宿主通道的审计与事后核验，不能承诺隔离任意编辑器。审计接收入口、额度累加、超限失败和回滚策略须经用户决定后才实施。
- 失败后禁止 primary-direct 连续自修形成无限循环；最多一次修复且累计仍≤10行，否则交 worker。此通道不授予提交、推送、部署、外部通信或不可逆操作权限。
