# 子代理思考档位与交付预算

[简体中文](worker-budgets.md) · [English](worker-budgets.en.md)

2026-09-22 用户授权调整原生 OpenAI Codex worker 的固定 Luna/max 策略。当前原生模型为 `gpt-6-luna`；主代理负责选择档位、拆分任务和最终验收，Pi 负责代码与测试编写。Reviewer、聚合 API 路由、文件权限和资源上限保持原有策略。

| 任务 | 显式 thinking | 使用条件 |
| --- | --- | --- |
| 精确、低风险修改 | low | 目标位置、变更行为和验收已明确 |
| 常规有界编码 | medium | 默认；一个任务交付一个行为 |
| 跨文件设计、原因不明的故障 | high | 有明确的分析目标和结束条件 |
| 困难推理 | max | 主代理记录为什么需要最高档位 |

档位由主代理判断，不是自动复杂度分类器。派发时明确传入 `thinking`，并在任务上下文记录选择理由。旧服务可以继续声明默认 max；显式参数优先，升级前不能把源码默认值当作运行服务事实。既有 API 平台路由的能力约束不因本次原生路由调整而自动改变。

每个任务包只负责一个明确行为，包含精确读写范围、验收条件和必要材料。计划为最终输出与验证交接保留约 20% 时间；提示词中的时间目标只是软约束，不能限制隐藏推理 token，也不保证按时交付。不要通过关闭思考、替换模型、原样重试或放宽权限来规避失败。

排队与执行使用独立时限。总执行时限覆盖认证、启动、模型与工具、结果输出和清理；缩短内部模型任务时间，不能扩大外层总时限。输出必须满足原有结构与验收规则；部分补丁、片段和超时任务不会自动转为成功。

源码中的内部沙箱预算为 `floor(总秒数 - 已用毫秒/1000 - min(15, 总秒数×10%))`。已用时间使用单调时钟，包括认证和派发准备；预留最多 15 秒用于返回与清理。若不足一个完整沙箱秒，派发在启动前返回 `PI_EXECUTION_BUDGET_EXHAUSTED`。例如总预算 180 秒、已用 20 秒时，内部任务为 145 秒，预留 15 秒。结果中的 `executionBudget` 提供计算依据，原始 `resourceLimits` 保持不变。提示中的提前交付目标与这部分清理预留不同；清理若超出预留，外层总截止仍可能终止任务。

验证应分别记录请求档位、成功交付数、验收质量、执行时间和可用的用量统计。同一任务的不同档位实验才可用于比较；一次短回显或单次代码交付不能证明整体提速或节省 token。2026-09-22 的 medium 心跳通过，仅证明该显式档位可以沿当前原生路线完成短回显。
