# 受限检查工具方案 / Restricted check tool proposal

状态：**仅设计，等待用户决定；未实现、未启用，也没有改变现有隔离保证。**

## 目标与边界

`yhwh_run_check` 让 Chesed 在任务快照中执行预先批准的检查，降低参数、退出码与 I/O 行为依赖猜测的风险。它不能代替宿主验收、Netzach 验证或 Geburah 独立审查。Windows 文件锁、PowerShell、注册表和原生 Windows 子进程行为仍必须在 Windows 宿主验证。

当前模型进程需要连接模型服务；因此不能简单声称整个 worker 已无网络。候选设计必须将检查放在**另一个无网络执行域**，通过固定 IPC 返回结果，不能把普通 shell 工具开放给 worker。

## 候选接口与授权

- 主代理在任务包的候选 `verify.commands` 中列出检查 ID、解释器、参数数组、相对工作目录和允许产生的输出路径。该字段目前不存在；以后若实施，须单独经过 T2 协议与安全审查。
- worker 只能按检查 ID 调用工具，不能传入新的命令、环境变量、路径或参数；运行器使用经宿主签名或可信存储绑定的规范化声明，不信任 worker 回传的声明。
- 不经过 shell；禁止命令拼接、管道、重定向、命令替换和动态环境覆盖。入口解释器用宿主固定绝对路径，不依赖 worker 的 PATH。
- 项目维护者维护项目白名单，宿主操作人批准其版本与摘要；主代理只能从已批准的白名单选择。任务中的声明本身不能扩大权限。未知检查或摘要漂移先拒绝，再由宿主验证。
- 白名单不是仅允许 `npm test` 等命令名：测试脚本本身就是代码执行。运行器必须限制解释器、启动入口、快照来源、可写输出和依赖缓存，承认项目代码在检查域内可执行任意逻辑。

## 隔离与配额

每次检查采用独立 WSL bubblewrap 实例及 cgroup：120 秒硬上限、合计输出 256 KiB、进程数 64，并继承任务剩余时间、内存与 CPU 上限中更严格的限制。超时终止整个进程组并等待收尾；输出超限明确失败，不把截断输出当作完成证据。

检查域无网络、无 Windows interop、无宿主盘挂载、无模型认证文件或 FD3 凭据、无 worker home、无宿主套接字。只挂载任务源快照、只读依赖缓存和独立的临时输出目录。worker 与运行器之间只传检查 ID 和受限结果；不能获得新文件访问权。

测试常需生成缓存、覆盖率或编译产物；这些写入仅在批准的检查输出目录中允许。不得把依赖目录、fixture 或源快照改成可写以便通过检查。候选实现须有逃逸、符号链接、资源耗尽、网络与凭据不可达的实机负例，不能只靠配置声明证明隔离。

## 依赖缓存准备

缓存由宿主的独立安装步骤联网准备，核对锁文件与内容摘要后封存；检查运行期间不安装依赖、不联网补齐。缺失或不匹配时返回 `dependency_unavailable`，交回宿主，而不是修改沙箱策略。

| 语言 | 候选只读缓存 | 检查时的限制 |
| --- | --- | --- |
| Node.js | 按锁文件构建的 node_modules 与固定 Node | npm scripts 必须解析成已批准的入口；缓存写入另放临时目录 |
| Python | 固定解释器与按哈希锁定的 wheel/venv | 不执行 pip；禁止用户 site；字节码缓存写临时目录或禁用 |
| C/C++ | 固定编译器、sysroot、头文件与库 | 编译产物仅写批准的临时 build 目录 |
| C# | 固定 SDK 与按锁文件准备的 NuGet 包 | restore 禁网；中间文件只进临时 obj/bin |
| Java | 固定 JDK 与预解析的 Maven/Gradle 依赖 | 离线模式；daemon 与缓存写入隔离；缓存缺失退回宿主 |
| Go | 固定工具链、模块缓存与标准库 | GOPROXY=off；编译缓存独立；禁止下载工具链 |
| Rust | 固定工具链、vendor/registry 缓存 | cargo offline/frozen；build.rs 仍属于检查域内代码执行 |

## 证据与失败回退

每次调用写入独立 `sandboxEvidence`：请求/检查 ID、白名单及输入摘要、解释器与参数、开始/结束时间、退出码、信号、启动错误、超时、输出是否超限、输出摘要与摘要哈希、收尾状态。日志按现有凭据规则脱敏；保留证据来源，不能重命名为 hostEvidence。

成功必须同时满足退出码 0、无启动错误、无终止信号、未超时、未输出超限且收尾成功；stderr 非空不代表失败。主代理仍实际执行任务要求的宿主检查，并用现有 `record_host_verification` 提交宿主事实。sandboxEvidence 不自动把任务变为 completed，也不能伪造宿主凭据或独立审查结论。

不可用、依赖缺失、平台不适用、资源超限或收尾异常均明确返回原因；worker 可以交付未验证补丁，主代理转入宿主验证。禁止改用宿主 shell、联网执行、切换 provider 或放宽隔离作为回退。

## 需要用户决定

建议先批准一个**单独的 T2 原型任务**：只支持固定 Node 语法检查与 node:test，默认关闭；先完成隔离负例、真实冒烟与独立审查，再决定是否上线。Python 和编译语言等原型通过后逐项加入。

本方案未批准前，不实现 `yhwh_run_check`、不增加 `verify.commands` 协议、不授予 worker 执行能力。安装、CI 和后续部署必须继续如实区分完成与未验证状态。
