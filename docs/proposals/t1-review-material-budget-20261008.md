# T1 审查材料预算提案（待用户确认）

状态：仅为候选方案，尚未生效。当前 T1 仍使用整个 reviewPacket 不超过 10 KB 的规则；本文件不改网关、活动模板、宿主副本或本次审查的准入。

用户请求：diff 不计入上限；其他证据和说明 ≤ 8 KB；总大小 ≤ 24 KB；超过时按提交拆分审查。

## 建议规则

T1 必须提供当前补丁的完整 diff、需求、相关上下文和实际宿主验证。diff 不计入“其他证据和说明”预算；其他证据和说明最多 8 KiB（8,192 字节）；完整审查材料最多 24 KiB（24,576 字节）。按 UTF-8 字节计量，不按字符数。

拟实施时，将完整 reviewPacket 序列化为 JSON 计算总大小；仅将已明确标记且经过校验的 diff 内容置为空字符串，保留结构、字段、来源及哈希，再序列化计算非 diff 大小。说明、测试输出或上下文代码不能冒充 diff。完整 diff 必须绑定提交范围、当前文件清单与补丁指纹，不能截断、只给文件名，或让主代理自行估算字节数。提示词和输出 schema 的开销另行报告，继续服从审查器的完整输入安全上限。

总大小超过 24 KiB 时，按提交范围拆分审查材料，每份都含该范围的完整 diff、必要上下文与当前宿主证据。拆分只是材料组织方式，不降低整个目标的等级、不重置 parent/anchor、审核计数、总时间或模型执行历史。每份说明其他提交的依赖、已有审查结果及尚未解决的阻塞意见。审查人必须能够判断跨提交影响；不能通过拆分省略跨提交上下文或超限材料。单个提交无法满足预算，或拆分后无法完整判断整体行为时，停止并请用户决定，不自动增加额度或拆小实现来绕过审查。

所有必需范围通过后才接受整个目标；最终合并状态还须有与同一最终补丁绑定的宿主验证。T1 非阻塞意见仍为附条件通过，不因建议重复审查；既有模型、独立性、阶段和配额不变。

## 确认后的实施范围与验证

用户确认后，另行修改分级表、核心规则、审查材料参考、对应技能及网关计量逻辑，同步宿主副本并验证一致性。本提案本身不能为这些修改授权或自行生效。

测试应覆盖两个预算的精确边界及多字节文本，伪装 diff 的说明、缺少或截断的补丁、来源/指纹漂移，以及提交拆分后配额和阻塞意见连续保留。确认部署后才切换活动规则，并保留旧规则和回滚记录。
