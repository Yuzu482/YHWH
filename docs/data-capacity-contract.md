# 补丁、结果与审查材料容量契约

这些限制属于不同层，不能互相代替。本次只统一来源、测量与失败位置，不扩大预算。

| 层 | 上限 | 测量对象 |
| --- | --- | --- |
| 补丁 | 4 MiB UTF-8 | 完整补丁原始字节 |
| 宿主完整结果 | 4,194,304 UTF-16 单位 | 脱敏后的完整导出 JSON，包含转义和元数据 |
| 结果分页 | 每页65,536 UTF-16 单位，最多128页 | JSON字符串的 UTF-16 偏移；摘要校验使用完整 UTF-8 |
| 单条持久化记录 | 32 MiB UTF-8 | 完整落盘 JSON，包括包装、摘要字段及末尾换行 |
| T1审查材料 | 非 diff 8 KiB；总计24 KiB UTF-8 | 标准化、脱敏、分块后的完整 reviewPacket |
| T2审查材料 | 总计128 KiB UTF-8 | 同上；每段仍最多32个字符串，每字符串最多8,000 UTF-16单位 |

容量常量位于 `payload/pi-dispatch/extensions/data-capacity.js`。预算以内使用 `<=`；UTF-8字节、UTF-16单位、token不混用。JSON转义、脱敏和包装会增加长度，因此4 MiB补丁不保证能与其他字段一起进入宿主完整结果。

进入宿主待验证状态前，同时检查持久化原始记录、pending记录、实际导出投影及实时返回投影，且检查早于创建宿主记录目录。普通模型结果发布完成契约前也检查完整导出容量，失败时不保留成功契约。写入宿主证明或Netzach证明前，用与读回相同的纯投影函数检查最终结果。原有证明完整性、角色验证与必要审查继续执行。

超出宿主读取上限返回 `PI_RESULT_CAPACITY_EXCEEDED`；落盘记录超限返回 `PI_RESULT_OVERSIZED`。错误包含 `location`、`unit`、`actual`、`limit`，不包含原始正文。已执行模型不记成未启动。网关交付失败保留完整原始结果与补丁，普通分页恢复入口仍然可用；不会截断、自动重跑、清空账本或自动接受。落盘失败继续保护唯一副本并暂停新模型启动。

新pending在创建目录和写入前，还按本任务的实际检查数量预留后续证明空间。`inspectHostCompletionCapacity`复用相同纯投影，分别计算宿主成功、宿主失败及适用的Netzach成功结果；已知检查名、契约和原结果保持精确，命令/输出使用现有2048/4096 UTF-16单位上限及每单位最多6个JSON转义字符的保守界。`HOST_VERIFICATION_LIMITS`与证明校验共用原数值，最多32项；不新增实际证据、不写入估算证明、不提高完整结果或缓存预算。超限位置为`host.completionReserve`，诊断含投影大小、预留增长量和剩余空间。

预留会减少新任务可用于正文的空间：一项检查约预留37千UTF-16单位，32项最大检查约1.2百万单位；实际值取决于已知内容。达到保留后的边界可以准入，超过一单位提前拒绝，避免补丁应用后才发现证明放不下。该界只针对现有合法证据的结果容量，不承诺磁盘可写、角色结果有效、未来schema不变或任务一定成功。无效角色的completed投影标为`computable:false`、`actual:null`，不按0计算，也不声称可以完成。检查名在脱敏前校验长度，脱敏后可能增长而无法提交匹配的名字，这是既有语义限制，未在本轮改变。

旧pending按原身份和摘要继续幂等重放，不追溯施加新的预留规则；历史任务仍可能在增加证明时超限。这时不写证明，原pending和结果保留，需检查错误位置、减少重复元数据或另行规划较小的可验收改动。不得记为已完成，也不得自动换requestId重跑。原来的真实证明写入前精确检查继续执行。

## 提前预算检查

在宿主已准备完整 diff、必要上下文和真实证据后，或在派发前检查已有材料时，使用只读诊断入口：

```powershell
node payload/pi-dispatch/scripts/host-handoff-client.mjs review-budget material.json new-budget.json
```

输入字段与 `buildReviewPacket` 一致：`stage`、`tier`、`requirements`、`changes`、`context`、`verification`、`changedFiles`，各内容为字符串数组；可提供 `trustedPatch` 作完整diff字节相等检查。命令只读取此输入并排他创建新报告，不读取源文件、不执行检查或模型、不记录证明、不派发审查。

报告包含实际非diff／总字节数、各部分占用、超限位置和处理动作。没有绑定diff时，非diff占用保守包含全部内容，另列有diff豁免的估计；`requiresTrustedDiffBinding`为true，不能将估计当成网关准入。调用方传入的相等补丁也不是账本证明，正式网关仍必须核验可信补丁绑定。

当正常按摘录和行边界分块、以及原有固定长度回退都超过32个字符串时，再尝试跨摘录重新打包，仅使用字符串更少的布局。changes保持各摘录直接拼接的字节不变；其他段用一个换行分隔原摘录，全文、顺序和来源标注保留。CRLF和代理对边界仍受保护，不修剪空白、不去重、不截断；无法合法分块的纯空白区间继续拒绝。脱敏沿用每个原摘录的既有处理；这不是跨摘录分裂凭据的新检测器。

预算诊断另给剩余/超出字节数。CLI摘要的`budgetFits`表示大小检查是否通过，`ready`和`admissionReady`始终为false；结构、可信来源及实际独立审查仍有各自的准入要求。T1预审阶段或非数组content会返回明确材料错误，避免把估算失败误当可派发。

超限按真实提交范围组织完整审查，保留整个目标的等级、身份、配额、依赖、未解决意见和最终组合证据。不会自动创建提交、截断diff、丢弃必要上下文或增加审查次数；单个提交仍放不下或配额不足时交给用户决定。
