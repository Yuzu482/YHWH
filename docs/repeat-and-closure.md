# Milestone 与收尾

新写入任务按独立验收目标声明 `milestone`，不把整站阶段视为无限修补额度。原则上一个目标不超过五次派发、三个文件组；跨 requestId 保留同一身份与全部失败。T2 的预审批准必须绑定完整 milestone 定义列表。

项目检查由宿主登记。沙箱检查不可用只产生警告并要求 worker 如实报告未验证，不能替代宿主验收或获得新的执行权限。原有模型、档位、沙箱、资源和审查材料预算不变。

连续两次真实失败后必须提交精确诊断；一次诊断只放行一次后续尝试。更换目标、父任务或目录来避开失败历史违反约定。网关可以验证声明与证据身份，不能证明两个不同自然语言目标在语义上相同。

一次诊断在预留尝试时消耗，即使确定未启动也不自动退额。宿主可以提交 `afterRequestId`，精确指向消耗该诊断的最新、已确定未启动的失败尝试，显式记录一份新诊断；旧诊断保持已消耗。未知执行、已启动、存在后续尝试或旧记录缺少消耗者身份时拒绝此恢复，不能自动重试或推断历史身份。

新派发只在观察到模型开始执行后取代同一 milestone 尚未应用的旧补丁。应用中的不确定结果需要核对，不能直接重试。宿主通过、独立审查和真实接受分别记录；不得补写历史接受。

收尾读取 `get_workflow` 的未关闭事项及分页游标。旧记录不补猜 milestone，接受或时间证据缺失明确标为未知。`abandon_artifact` 只追加精确补丁哈希与原因，不删除旧证据；不允许放弃已接受或接受状态不确定的记录。

## 工作线限制

同一时间最多一条活跃、未合并的 YHWH 维护工作线。启动下一项优化之前，上一项必须已合并、部署并通过生产检查，或明确放弃并保留原因与证据。已冻结、明确暂缓的旧提案不能与当前候选并行写代码，也不算完成。候选准备好、CI 通过、合并、部署与部署后验收分别报告。

## 恢复与容量

milestone sidecar 最多保存 1024 个目标、4096 次尝试、4096 份诊断、4096 条旧记录放弃状态，文件最多 4 MiB。满额或写入失败时拒绝新执行；不能删除唯一结果、清空失败历史或自动增加预算。锁遗留、执行状态不确定或应用中重启需要依据原 requestId 和真实产物进行人工或经批准的维护核对；不自动解锁、不自动换 ID 重跑。

`reconcile_milestone` 默认只检查。宿主提供原 requestId、请求摘要和精确结果指纹后，只有不可变派发账本证明的终止失败可以 finalize：明确未启动，或明确已启动且进程清理成功、退出码已知。实际启动的失败保留一次失败计数；未知执行、应用中断和未完成产物仍阻塞，不推断为零启动，不自动重派。重复 finalize 返回同一记录，原失败与请求身份不变。

接下来的真实业务 20 次 Chesed 派发与启用后 48 小时观察单独统计。数量不足如实报告，不制造业务任务凑数；测试夹具中的接受事件只属于隔离测试账本。
