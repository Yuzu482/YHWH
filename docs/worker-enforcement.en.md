YHWH defaults to `strict` mode and checks worker routes before managed model execution, including no-file requests that can still produce code. Ordinary workers admit only native `openai-codex/gpt-6-luna`, or a host-configured `yhwh-worker-api` route with Luna as its semantic model. External hosts may select Sol, Terra or other models as their primary; these models cannot execute as ordinary Pi workers.

Two controlled exceptions remain: a Sonnet reviewer passing existing role binding, complete review-material and no-tools checks, and a tool-free heartbeat whose fixed echo prompt is generated by the gateway. A task cannot gain an exception by naming itself reviewer or adding a probe field. Model discovery lists support inspection and probes, not general worker admission.

Independent headless CLIs bypass Pi role validation, so strict mode rejects their model execution, including single, session, batch and streaming paths. Version, help, Doctor and file-fingerprint checks remain available. A host operator must explicitly disable the additional restriction to restore the existing headless behavior.

## Switch

The host process environment variable `YHWH_WORKER_ENFORCEMENT` accepts exactly two values:

| Value | Behavior |
| --- | --- |
| Unset or `strict` | Enforce restrictions |
| `off` | Disable the additional restriction and restore existing entry behavior |
| Anything else, including a typo | Reject execution without a permissive fallback |

Set `$env:YHWH_WORKER_ENFORCEMENT = 'strict'` or `'off'` in the PowerShell session that starts YHWH, then launch normally. An already-running service does not inherit environment changes from another terminal; restart through the existing managed procedure. A temporary terminal setting is not automatically persisted across logins. Inspect `list_capabilities.workerEnforcement` for the running mode.

Tasks, workspace configuration and per-request fields cannot override the switch; it is not forwarded to Pi child processes. Turning it off does not weaken existing role, provider, review-material, file-access or authorization checks, authorize primary coding, or trigger model fallback.

## Boundary

Hard enforcement here means that YHWH-managed entry points reject requests before authentication or model process creation. It does not revoke an external Codex, Claude or other client's own terminal/editor permissions, or prevent an operator with host privileges from changing the code or switch. External primary tools remain governed by the [primary ownership policy](coordinator-only.en.md). Capability metadata and one successful heartbeat do not prove OS isolation or complete historical compliance.
